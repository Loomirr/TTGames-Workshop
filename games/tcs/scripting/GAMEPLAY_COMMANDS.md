# Gameplay command inventory

[Guide index](README.md) · [Command reference](COMMANDS.md) · [Machine-readable full index](COMMAND_INDEX.json)

This lists the 170 condition and 207 action entries in the gameplay tables.
Together with the core tables, the index contains 480 registration entries.
Four kind/name pairs occur in both layers, leaving 218 distinct conditions and
258 distinct actions. Gameplay entries take precedence; see
[the overlapping names](EXECUTION.md#registration-preparation-and-evaluation-are-different-stages).
These are names and addresses, not complete command signatures. Arguments and
behaviour must be checked per handler. Build identification and lookup order
are documented in the [name audit](UNRESOLVED_NAMES.md#tables-and-validation).

Do not treat a null handler as an unknown name: registered special conditions
can use interpreter state. Unknown-name failure means the entire name lookup
returned no entry. The JSON index also includes condition preparation callbacks;
an initialized condition is not always equivalent to a freshly parsed node.

Every row in the JSON index was checked against the native table bytes, and
all 476 distinct kind/name pairs resolved to their expected entry when the
original lookup instructions were executed in an emulator. This validates
lookup coverage, not the behaviour of every handler.
