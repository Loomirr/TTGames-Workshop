# Character and cutscene recovery

Character 0.5.10 and CU3 0.1.19 repair regressions found when testing complete
characters after the 0.5.7–0.5.9 changes. These changes retain source provenance,
conflicting-edit rejection, bounded archive/DDS reads and explicit format gates.

## What went wrong

- Native character definitions use paths relative to `Chars`, such as
  `Minifigs/Super_Characters/Body/...`. Strict root-relative lookup missed those
  textures and faces. Models could import with generic blue materials instead
  of costume printing. The resolver now checks the declared path, then its
  explicit `Chars/` equivalent. It does not discard directory names or search
  unrelated folders for matching basenames. Both installed archives and loose
  extracted trees use this rule.
- The new variant validator recognized ordinary rigid/skin records but rejected
  the observed facial morph-skin kind 3. It also assumed variant draw labels and
  representation kinds must match. Original cape LODs rename draws, and distant
  face LODs replace morph skins with rigid surfaces. The counted native metadata
  remap establishes their association; each endpoint still requires valid
  ownership, geometry and skin palettes. Unknown kinds remain rejected.
- Hobbit HGOL 12 uses typed trailer arrays with a second joint map and scale.
  Avengers HGOL 17 adds four opaque bytes and a zero flag. These observed layouts
  now have explicit handling, bounded resource boundaries and retained opaque
  data. This does not enable arbitrary other HGOL versions.

- Blender 5.2.2's legacy custom-normal encoder crashed on original LB3 Batman
  power-helmet parts containing repeated-index triangles. The importer now
  preserves the triangles and supplies authored evaluated corner normals through
  the Set Mesh Normal node. Blender versions without that node use automatic
  shading for these exceptional parts and retain a limitation on the object.
  Native geometry is not cleaned, welded or reindexed.

## Changes retained from the update

The mixed-normal correction, preview-setting registration recovery, case-insensitive
facial-name handling, scoped animation lookup, material diagnostics and verified
Avengers archive-index extension remain. Their purpose is useful; the complete
character tests exposed integration assumptions that isolated fixtures missed.

## Validation scope

Validation records and game-derived images/scenes remain under ignored `local/`.
Checks cover repository tests, Blender registration and preview helpers, original
character imports, native export/reimport and rendered sample inspection.
Nine rendered character samples were inspected: LMSH1 Wolverine, Magneto,
Vulture and Iron Man Mark 6; Hobbit Thráin; LB3 Alfred and Batman; Avengers
Captain America AOU and Iron Man Mark 43. Their declared active attachments
loaded without attachment warnings. Five character-specific idle clips loaded
without animation warnings, covering all four native character profiles.

Original-source native bundle checks passed for Wolverine, Thráin, Batman and
Captain America: unchanged export/reimport, identical instances, rejected
conflicting edits in both orders, and a decoded UV edit. These are byte/structure
checks, not an in-game test. The rendered material checks were performed
separately after correcting character-relative texture lookup.

This is not whole-roster or in-game fidelity certification. Native shader
translation, facial depth clipping, stage assembly and additional game layouts
remain incomplete. Live faces approximate native depth tests and should be
inspected through the preview camera; composed rendering is a separate check.
Existing broken imports need reimporting to recover missing geometry/textures.


## Completed recovery checks

- 522 portable repository tests, source syntax, documentation links, package
  hashes/integrity and asset-exclusion checks passed.
- Blender 5.2.2 package registration, preview-setting recovery, mixed normals,
  repeated-index normals, facial mask grouping and compositor checks passed.
- Six toolbox checks and all nine standalone GUI package checks passed.
- The original LB3 power helmet passed native no-op export/reimport and the
  decoded UV edit/conflict checks after the normal workaround.
- LB3 `2BATCAVEFIGHT_INTRO_NXG` assembled 26 actor/attachment model instances
  and 22 cameras. LMSH1 `STARKTOWER_INTRO_NXG` assembled 7 model instances and
  13 cameras. Both reports had no unresolved actor nodes or assembly issues;
  sample frames rendered and the scenes saved. These recovery runs deliberately
  disabled static environments to isolate actor recovery. They do not validate
  complete stages, lighting, effects, audio or camera fidelity.

The current limits on native materials, depth-mask previews and independent
exporter work remain. No in-game test or new game support is claimed by this
recovery. Previous handoff notes and all game-derived validation artifacts stay
local; public packages contain our tools and documentation only.
